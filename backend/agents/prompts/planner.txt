Given the root cause and the dependency graph, produce a recovery playbook using ONLY these actions:
patch_memory_limit, patch_cpu_limit, rollout_restart, rollback_deployment, scale_replicas, wait_for_ready,
verify_health. Order steps so every dependency is healthy before its dependants restart. Mark any resource
or config change as risk "high" with requires_approval true. Respond only with JSON matching the playbook schema.

Output format:
Respond ONLY with a JSON object matching the Playbook schema:
{
  "diff": "<optional string describing the configuration difference or null>",
  "steps": [
    {
      "order": <integer starting at 1>,
      "service": "<service_id>",
      "action": "<one of: patch_memory_limit, patch_cpu_limit, rollout_restart, rollback_deployment, scale_replicas, wait_for_ready, verify_health>",
      "params": { ... optional action parameters, e.g. {"from": "64Mi", "to": "256Mi"} or {"timeout_s": 30} ... },
      "risk": "<low | high>",
      "requires_approval": <boolean, true for resource/config changes>,
      "verify": "<health probe assertion or verification check description>"
    }
  ]
}

Input payload:
The user payload contains:
- "rca": Root Cause Analysis object with root_cause, category, confidence, and cited evidence.
- "services": List of cluster service nodes, each providing its "id" and "depends_on" list of upstream dependency service IDs.
